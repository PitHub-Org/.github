# PitHub
## Lewis University – Document & Media Sharing Platform

### Overview

Welcome to the official GitHub organization for **PitHub**, a Lewis University-exclusive document and media sharing platform designed to provide students and faculty members with a centralized environment for organizing, managing, and sharing educational resources.

PitHub allows authorized university users to organize documents, videos, and other educational resources into **Classes**, providing an accessible and structured learning environment.

This organization serves as the central development and collaboration hub for the PitHub platform. It hosts and manages the project's source code, technical documentation, and related repositories while supporting the continued development, maintenance, and improvement of the application.

PitHub is intended to be a continuously evolving project, with successive Scrum teams contributing to its development across academic semesters.

---

### Project Architecture

PitHub follows a serverless React architecture, utilizing Google Firebase for authentication, data persistence, file storage, and application hosting.

**Primary Technologies:**

- **Frontend:** React, Vite, JavaScript
- **Authentication:** Firebase Authentication with Google Sign-In
- **Database:** Cloud Firestore
- **File Storage:** Firebase Cloud Storage
- **Hosting:** Firebase App Hosting / Firebase Hosting

### Development Teams & Project Continuity

PitHub is designed to support ongoing development through successive Scrum teams recruited to maintain and improve the platform.

Each development cycle may involve new teams responsible for continuing existing work, implementing new functionality, addressing technical debt, and improving the overall user experience.

Development teams are expected to:

- Familiarize themselves with the existing architecture and implementation.
- Maintain and improve existing application functionality.
- Implement new features based on prioritized requirements.
- Follow established development standards and workflows.
- Maintain accurate technical and project documentation.
- Ensure a smooth transition of project knowledge and responsibilities to succeeding teams.

The goal is to preserve continuity, maintainability, and consistent development practices as PitHub evolves.

---

### Development Standards & Workflow

All repositories within this organization should follow consistent development practices to maintain code quality, collaboration, and project stability.

- **Branching:** Use `main` for production-ready code, `dev` for active development, and feature branches for individual changes.
- **Pull Requests:** Submit changes through Pull Requests and require appropriate reviews before merging.
- **Code Quality:** Follow consistent coding conventions, maintain readable code, and document significant changes.
- **Testing:** Test features before merging and use Firebase Emulators when appropriate.
- **Security:** Never commit credentials, API secrets, or sensitive configuration files. Address dependency vulnerabilities promptly.
- **Documentation:** Keep relevant technical documentation and repository README files up to date.

Direct pushes to `main` should remain disabled, with appropriate branch protection rules and automated status checks enforced.
